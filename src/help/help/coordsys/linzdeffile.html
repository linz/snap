LINZ deformation file format

The LINZ deformation model format is used to represent complex deformation fields which can comprise both an ongoing national deformation model and local perturbations to this field due to earthquakes or other deformation.

The deformation file used by SNAP is a binary file format. The file is generated from a number of text files using the linzdeformationmodel.py script supplied with SNAP. The main file is an index file which defines the deformation model, and the deformation sequences and components of which it comprises (as described in the LINZ deformation model). Each component is in turn represented by either a gridded data file or triangulated data file. Currently LINZ deformation models have only used the grid file format - it is likely the triangulated file format will be deprecated.

Each component's source file can be a pre-built binary file, or an ASCII source file from which the binary is built. The latter is preferable, since it ensures every component ends up built with the same endianness.

File structure

The index file is structured with a header section followed by one or more deformation sequences. Each sequence has one or more deformation components. Each record comprises a code defining the content of the record, followed by the value of the record. Dates in the file are formatted as dd-mmm-yyyy, for example “20-Jan-2004”. This can optionally be followed by a time such as “12:30”

The header section should contain the following records:

Code

Type

Description

DEFORMATION_MODEL

string

The name of the deformation model

FORMAT

string

Defines the variant of the binary file format to generate – see Which version should I use? below for the possible values.

START_DATE

date

The first date for which the model may be used – dates before this are invalid

END_DATE

date

The last date for which the model may be used – dates after this are invalid

COORDSYS

string

A code for the coordinate system in which the deformation is defined – eg NZGD2000.

The header is followed by the deformation model version information, then one or more deformation sequence sections, each of which is followed by one or more deformation components. The records in each of these sections are version-specific, as described below.

Which version should I use?

There have been three versions of the deformation file format. Each is a strict increase in complexity over the last, so it is worth understanding version 1 before moving on to version 2, and version 2 before version 3.

Version 1 (FORMAT = LINZDEF1L or LINZDEF1B) provides basic grids and a simple time model: each component has a single reference date, and is evaluated as zero, fixed, or interpolated either side of it.

Version 2 (FORMAT = LINZDEF2L or LINZDEF2B) adds nested sequences (so that only the first spatially matching component of a sequence is used, rather than summing all of them), and lets each component define a more flexible time model of its own, including piecewise-linear and velocity-based scaling.

Version 3 (FORMAT = LINZDEF3L or LINZDEF3B) adds support for holding multiple versions of the deformation model in a single file, each with its own version date and description. Version 3 (little-endian, LINZDEF3L) is the current preferred format for SNAP.
