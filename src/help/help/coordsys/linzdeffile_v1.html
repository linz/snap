LINZ deformation file format version 1

Version 1 is the original, simplest variant of the LINZ deformation file format: each sequence has a single data type (deformation or velocity), and each component's contribution over time is controlled by a single reference date with a zero/fixed/interpolate rule either side of it.

Set FORMAT to LINZDEF1L (little-endian) or LINZDEF1B (big-endian) in the header to select this version – see the shared header section for the other header records.

Dates on this page are formatted as dd-mmm-yyyy, for example “20-Jan-2004”, optionally followed by a time such as “12:30”.

Model header records

In addition to the shared header records, version 1 requires the following in the header section, before the first sequence:

Code

Type

Description

VERSION_NUMBER

number

The version of the deformation model – digits, optionally with a single decimal point (eg “1.0”).

VERSION_DATE

date

A human-readable record of when this version became authoritative. SNAP does not use this value in any calculation – it is descriptive only.

DESCRIPTION
text ...
END_DESCRIPTION

text

A free-form, multi-line description of the model. Any text is accepted, up to the terminating END_DESCRIPTION line.

These header records, together with the shared ones, may appear in any order, except that DEFORMATION_MODEL must be the first record in the file, and FORMAT must appear before the first DEFORMATION_SEQUENCE record.

Sequence records

Each deformation sequence section should contain the following records:

Code

Type

Description

DEFORMATION_SEQUENCE

string

The name of the sequence (eg National model, Arthurs’ Pass earthquake).

DATA_TYPE

string

Either “deformation” or “velocity”. Determines how the sequence's components combine over time – see below. If omitted, the sequence is treated as “deformation” type.

DIMENSION

1, 2, 3

The dimension of the deformation (1 = height only, 2 = horizontal only, 3 = 3d deformation).

START_DATE

date

The first date at which the sequence applies – it is assumed to be zero before this.

END_DATE

date

The last date at which the sequence applies – it is assumed to be zero after this date.

ZERO_BEYOND_RANGE

string

Either “yes” or “no”. If “yes”, the sequence contributes zero for points beyond the spatial extent of its components. If “no”, evaluating a point beyond that extent fails with an error – and since the model's total deformation is the sum of every sequence, that error aborts the whole calculation, not just this sequence's contribution. If omitted, defaults to “yes”.

DESCRIPTION
text ...
END_DESCRIPTION

text

A free-form, multi-line description of the sequence. Any text is accepted, up to the terminating END_DESCRIPTION line.

Component records

Each deformation component should contain the following records:

Code

Type

Description

DEFORMATION_COMPONENT

string

The name of the grid or triangulation data file containing the model. This must match the dimension of the sequence. The name may be followed by additional parameters to be used to generate the grid or trig file (by the grid.py or trig.py scripts, respectively).

MODEL_TYPE

string

Either “grid” or “trig”.

REF_DATE

date

The single reference date used to evaluate this component over time.

BEFORE_REF_DATE

string

One of “zero”, “fixed”, or “interpolate”. Defines how the component is evaluated before its reference date. If omitted, defaults to “interpolate”.

AFTER_REF_DATE

string

One of “zero”, “fixed”, or “interpolate”, equivalent to BEFORE_REF_DATE but for dates after the reference date. If omitted, defaults to “interpolate”.

DESCRIPTION
text ...
END_DESCRIPTION

text

A free-form, multi-line description of the component. Any text is accepted, up to the terminating END_DESCRIPTION line.

The three options for BEFORE_REF_DATE/AFTER_REF_DATE mean:

zero

The component is not evaluated on this side of the reference date – its contribution is zero.

fixed

If the sequence's DATA_TYPE is “deformation”, the component's value is held constant at whatever it is at the reference date. If the sequence's DATA_TYPE is “velocity”, deformation continues to accumulate at the component's velocity.

interpolate

If the sequence's DATA_TYPE is “deformation”, the value is interpolated towards the neighbouring component earlier or later in the same sequence, if there is one. If the sequence's DATA_TYPE is “velocity”, deformation accumulates at the component's velocity, exactly as “fixed” does.

If the sequence's DATA_TYPE is “deformation”, components must be listed in ascending order of reference date; the deformation at a given time comes from the components immediately before and after that time (or the two nearest components, if the time is beyond the range of the sequence's own components), combined according to each component's own before/after-reference-date setting. If the sequence's DATA_TYPE is “velocity”, the velocities of every applicable component are simply added together – such a sequence usually has only one component.

Worked example

The example on the LINZ deformation file format page has two sequences: a national velocity model, and a Fiordland earthquake patch. Here is how their own BEFORE_REF_DATE/AFTER_REF_DATE settings play out at specific dates.

The national model is a velocity-type component, REF_DATE 1-Jan-2000, both BEFORE_REF_DATE/AFTER_REF_DATE interpolate – since velocity sequences accumulate deformation continuously either side of the reference date, this gives a steady, ongoing linear trend:

Date

Deformation (relative to 1-Jan-2000)

1-Jan-1990

-10 years × velocity

1-Jan-2000 (REF_DATE)

0 (by definition)

1-Jan-2010

+10 years × velocity

The Fiordland patch is a deformation-type component, REF_DATE 15-Jul-2009 (the earthquake date), BEFORE_REF_DATE zero, AFTER_REF_DATE fixed – nothing before the earthquake, then the full offset held constant afterwards:

Date

Deformation

14-Jul-2009 (before REF_DATE)

zero

15-Jul-2009 (REF_DATE)

full patch offset

16-Jul-2009 onwards (after REF_DATE)

full patch offset (fixed)

DEFORMATION_MODEL NZGD2000 deformation model
FORMAT LINZDEF1B
START_DATE 1-Jan-1850
END_DATE 1-Jan-2200
COORDSYS NZGD2000
VERSION_NUMBER 1.0
VERSION_DATE  12-Mar-2004
DESCRIPTION
This is the description of the model
This is a first try
END_DESCRIPTION

DEFORMATION_SEQUENCE National model
DATA_TYPE velocity
DIMENSION 2

DESCRIPTION
Deformation patch with single model, zero before, fixed after
END_DESCRIPTION
