LINZ deformation file format version 3

Version 3 of the LINZ deformation file format adds support for a single file holding more than one edition (version) of the deformation model. This is a subtle distinction versus v1/v2 files because adding a new DEFORMATION_SEQUENCE block with its own START_DATE already let them represent changes to a model over time, e.g. if a significant new earthquake occurred. However, what v1/v2 cannot do is preserve the model as it stood before that sequence existed. Once a new sequence is added, it becomes part of every calculation whose date falls within its own START_DATE/END_DATE, with no way to recover the answer the file would have given before the sequence existed. In v3 files, the VERSION keyword closes that gap: it allows the model's publication history to also be considered and recorded, not just the physical timeline of any one deformation event.

Sequence and component records are identical to version 2 (NESTED_SEQUENCE, TIME_MODEL etc.) – except for the new repeatable VERSION keyword described below, and two new sequence-level records, VERSION_START/ VERSION_END which allow them to document which of the file's VERSION blocks a given sequence belongs to.

Set FORMAT to LINZDEF3L (little-endian, the current preferred format for SNAP) or LINZDEF3B (big-endian) in the header to select this version – see the shared header section for the other header records. Unlike version 1 and version 2, version 3 has no additional records of its own at the model header level. Everything version-related moves into the repeatable VERSION record instead.

Unless otherwise specified, dates on this page are formatted as dd-mmm-yyyy, for example “20-Jan-2004”, optionally followed by a time such as “12:30”.

The VERSION record

The header section may contain one or more VERSION blocks, each introduced by a VERSION record whose value is the edition's own identifier. This is a new record, distinct from the VERSION_NUMBER record used in version 1/2. Each VERSION record must be followed by VERSION_DATE and DESCRIPTION records:

Code

Type

Description

VERSION

YYYYMMDD

The identifier of this edition of the deformation model. Must be exactly 8 digits, starting with “20” (e.g. “20090716”). Unlike VERSION_NUMBER in version 1/2, this is not free-form text – the exact YYYYMMDD format is required, not just recommended, since editions are ordered by comparing this value as a string.

VERSION_DATE

date

A human-readable record of when this edition became authoritative. Required – there is no default. As with version 1/2's model-level VERSION_DATE, SNAP does not use this value in any calculation – it is descriptive only.

DESCRIPTION
text ...
END_DESCRIPTION

text

A free-form, multi-line description of this edition. Required – there is no default, though the text itself may be empty. Any text is accepted, up to the terminating END_DESCRIPTION line.

SNAP always runs against exactly one edition of the model at a time: whichever VERSION block has the highest identifier is used by default. A coordinate system can instead pin the model to a specific edition – see the LINZDEF entry in the reference frame definition format. Every sequence is then either enabled or disabled for that edition, according to its own VERSION_START/VERSION_END – see below.

A VERSION is not itself a span of time the model applies over – that is what a sequence's own START_DATE/ END_DATE already describe, see the sequence records below. VERSION_START/VERSION_END answer a different question: which editions of the model definition include a given sequence at all? SNAP fixes the edition for an entire calculation regardless of the dates being computed. In the worked example below, a coordinate computed for 2015 under the “20040312” edition still omits the 2009 Fiordland earthquake sequence – not because 2015 falls outside that sequence's own time range, but because the sequence does not exist yet in that edition.

Sequence records

Each deformation sequence section should contain the following records – identical to version 2, except with VERSION_START/VERSION_END added:

Code

Type

Description

DEFORMATION_SEQUENCE

string

The name of the sequence (e.g. National model, Arthurs’ Pass earthquake).

DIMENSION

1, 2, 3

The dimension of the deformation (1 = height only, 2 = horizontal only, 3 = 3d deformation).

START_DATE

date

The first date at which the sequence applies – it is assumed to be zero before this.

END_DATE

date

The last date at which the sequence applies – it is assumed to be zero after this date.

ZERO_BEYOND_RANGE

string

Either “yes” or “no”. If “yes”, the sequence contributes zero for points beyond the spatial extent of its components. If “no”, evaluating a point beyond that extent fails with an error – and since the model's total deformation is the sum of every sequence, that error aborts the whole calculation, not just this sequence's contribution. If omitted, defaults to “yes”.

NESTED_SEQUENCE

string

Either “yes” or “no”. If “yes”, only the first component of the sequence (in sequence order) whose own spatial extent includes the evaluation point is used, and every other component of the same sequence is ignored. If “no”, every component of the sequence that covers the point is evaluated and all of their contributions are added together. Nesting only affects this one sequence's own components – every other sequence in the model is still added in as usual regardless of whether it is nested. If omitted, defaults to “yes”.

VERSION_START

YYYYMMDD

The identifier of the first VERSION in which this sequence exists. Required – there is no default. If the model's currently-selected edition is earlier than this, the sequence is disabled entirely (it contributes nothing, as if it were not in the file).

VERSION_END

YYYYMMDD, or 0

The identifier of the VERSION in which this sequence was revoked – the sequence is disabled from that edition onwards. Required – there is no default. Write “0” if the sequence has never been revoked (this is translated internally to a value that sorts after every real edition, so the sequence stays enabled in every edition that exists); a literal identifier disables it from that edition on.

DESCRIPTION
text ...
END_DESCRIPTION

text

A free-form, multi-line description of the sequence. Any text is accepted, up to the terminating END_DESCRIPTION line.

A sequence is enabled for a given selected edition exactly when VERSION_START ≤ selected edition < VERSION_END (comparing the YYYYMMDD identifiers as plain strings, which is why VERSION's exact 8-digit format matters). A disabled sequence is skipped entirely – it contributes nothing, exactly as if it were absent from the file for that edition.

VERSION_START/VERSION_END are still expected to follow the same YYYYMMDD format as VERSION, for the same reason: the comparison is done as a plain string, not as a date. The file format only rejects values over 8 characters – it does not require exactly 8. A shorter value, or one that is not a real date, is still compared as a plain string against the selected edition's identifier, and that comparison will not reliably match real chronological order unless YYYYMMDD is followed.

Owing to this lexical comparison of VERSION_START/VERSION_END to the selected edition, neither needs to match one of the file's own declared VERSION identifiers identically. They are only ever compared against whichever edition ends up being selected, whether that is the default (highest) edition or one a coordinate system has pinned to.

For example, with two editions VERSION 20040312 and VERSION 20090716, and three sequences – one with VERSION_START 20040312/ VERSION_END 0, one with VERSION_START 20090716/VERSION_END 0, and one with VERSION_START 20060101/VERSION_END 0 – a start date that matches neither declared edition:

Selected edition

Sequence starting 20040312

Sequence starting 20090716

Sequence starting 20060101

20040312

enabled

disabled (not introduced yet)

disabled (not introduced yet)

20090716

enabled

enabled

enabled

The sequence starting “20060101” behaves identically to the one starting “20090716”, because no declared edition falls between the two dates for the comparison to tell them apart. That only holds because each sequence's VERSION_END is 0 (unbounded) here – nothing caps how far forward the match can be pushed.

If both ends of a sequence's window fall strictly between two declared editions instead, the sequence can end up permanently disabled rather than just shifted to the next one. Suppose a file declares only two editions, VERSION 20040312 and VERSION 20120101, and a sequence has VERSION_START 20060101 and VERSION_END 20090101:

Selected edition

Comparison

Result

20040312

20060101 ≤ 20040312 < 20090101

false – disabled

20120101

20060101 ≤ 20120101 < 20090101

false – disabled

No declared edition ever falls inside [20060101, 20090101), so this sequence can never be enabled under any edition the file actually offers. The same would be true, unconditionally, if the sequence were specified with VERSION_END ≤ VERSION_START – no selected edition could ever satisfy VERSION_START ≤ selected edition < VERSION_END; this is not checked when the file is loaded.

Component records

Identical to version 2. See the TIME_MODEL record for the full derivation of PIECEWISE_LINEAR and VELOCITY.

Worked example

This is the same scenario as the version 2 worked example, except now split across two editions of the model: the national model was introduced first, and the Fiordland earthquake patch was added later when the model was revised to include it.

DEFORMATION_MODEL NZGD2000 deformation model
FORMAT LINZDEF3B
START_DATE 1-Jan-1850
END_DATE 1-Jan-2200
COORDSYS NZGD2000

VERSION 20040312
VERSION_DATE 12-Mar-2004
DESCRIPTION
This is the description of the model
This is a first try
END_DESCRIPTION

VERSION 20090716
VERSION_DATE 16-Jul-2009
DESCRIPTION
Updated to include the 15 July 2009 Fiordland earthquake
END_DESCRIPTION

# National model

DEFORMATION_SEQUENCE National model
DIMENSION 2
START_DATE 1-Jan-1850
END_DATE 1-Jan-2101
ZERO_BEYOND_RANGE no
VERSION_START 20040312
VERSION_END 0
DESCRIPTION
National velocity model
END_DESCRIPTION

DEFORMATION_COMPONENT velgrid.gdf
MODEL_TYPE grid
REF_DATE 1-Jan-2000
TIME_MODEL VELOCITY
DESCRIPTION
National velocity grid deformation model
END_DESCRIPTION

# 15 July 2009 Fiordland earthquake

DEFORMATION_SEQUENCE Fiordland earthquake 15 July 2009
DIMENSION 2
START_DATE 1-Jan-2020
END_DATE 1-Jan-2030
ZERO_BEYOND_RANGE yes
NESTED_SEQUENCE yes
VERSION_START 20090716
VERSION_END 0
DESCRIPTION
Deformation patch with single model, zero before, fixed after
END_DESCRIPTION

DEFORMATION_COMPONENT fiordland_20090715_a.trg -c
MODEL_TYPE trig
REF_DATE 15-Jul-2009
TIME_MODEL PIECEWISE_LINEAR 0.0 15-Jul-2009 0.8 20-Jul-2009 1.0
DESCRIPTION
Initial model of 15 July 2009 Fiordland earthquake
END_DESCRIPTION

DEFORMATION_COMPONENT fiordland_20090715_b.trg -c
MODEL_TYPE trig
REF_DATE 15-Jul-2009
TIME_MODEL PIECEWISE_LINEAR 0.0 15-Jul-2009 1.0
DESCRIPTION
Initial model of 15 July 2009 Fiordland earthquake (near-field)
END_DESCRIPTION

Under edition “20040312” (the model as originally published), only the National model sequence is enabled – the Fiordland sequence does not exist yet. Under edition “20090716” (the current, most recent edition, and so the one SNAP uses by default), both sequences are enabled.
